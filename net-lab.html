المحاكاة العملية

نظرة عامة

ثلاثة موجّهات في مثلث مع حاسوبين طرفيين. الهدف: إعداد OSPF في المنطقة 0 ومراقبة إعادة التقارب عند انقطاع وصلة.

  • R1–R2: 10.0.12.0/24
  • R2–R3: 10.0.23.0/24
  • R1–R3: 10.0.13.0/24
  • PC1 192.168.1.10 خلف R1 (البوابة 192.168.1.1)
  • PC2 192.168.3.10 خلف R3
اضغط ابدأ لتحميل طرفيات الأجهزة الخمسة وبدء العدّاد (60 دقيقة). تبقى الجلسات مفتوحة عند التنقل بين الأجهزة.

المهام

الموجّهات تعمل بـ FRR (vtysh). أجب في الحقول للتحقق الذاتي.

المهمة 1فحص
ابحث في مخرجات show interface brief عن العنوان 10.0.13.1.
المهمة 2اتصال
نفّذ show ip route في R1: هل توجد شبكة 192.168.3.0/24 في الجدول؟
المهمة 3OSPF
configure terminal ← router ospf ← ospf router-id 1.1.1.1 ← network 10.0.12.0/24 area 0 ... ثم end.
المهمة 4تحقق
إذا لم تكن 0٪ فتحقق من show ip route ospf على R1 و R3.
المهمة 5مسار
القفزة الأولى 192.168.1.1 (R1)، والثانية من شبكة 10.0.13.0/24.
المهمة 6تقارب
مؤقتات OSPF الافتراضية: Hello 10 ث، Dead 40 ث. لتقليل زمن التقارب: ip ospf hello-interval / dead-interval أو BFD.
أسئلة للنقاش: ما فائدة router-id؟ ما الفرق بين حالة 2-Way و Full؟ كيف يمكن تقليل زمن التقارب؟

الحلول

حاول حلّ المهام أولًا. الإعدادات أدناه تُكتب داخل vtysh بعد configure terminal.

R1
router ospf
 ospf router-id 1.1.1.1
 network 192.168.1.0/24 area 0
 network 10.0.12.0/24 area 0
 network 10.0.13.0/24 area 0
R2
router ospf
 ospf router-id 2.2.2.2
 network 10.0.12.0/24 area 0
 network 10.0.23.0/24 area 0
R3
router ospf
 ospf router-id 3.3.3.3
 network 192.168.3.0/24 area 0
 network 10.0.23.0/24 area 0
 network 10.0.13.0/24 area 0
إجابات مختصرة

2: لا يوجد مسار إلى 192.168.3.0/24 قبل OSPF · 3: Full · 4: 0٪ · 5: R1 ← R3 مباشرة · 6: حتى ~40 ث (Dead interval) عادةً، وأسرع إذا اكتُشف انقطاع الواجهة محليًا.
